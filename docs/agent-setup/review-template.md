# Review and completion evidence — proportional template

- Problem and resulting behavior:
- Scope, diff/revision and relevant accepted decisions:
- Acceptance scenarios and their tests/manual evidence:
- Commands executed, environment, results and pending checks:
- SOLID/Clean Code: cohesion, contract substitution, dependency direction and visible effects:
- TDD evidence and refactoring baseline/behavior-preservation checks, where applicable:
- Architecture boundaries, data invariants and contract compatibility:
- Security/permission implications and applicable checks:
- Contract/schema compatibility evidence and supported consumer/provider versions:
- Final artifact/container checks and immutable identity promoted:
- CI required-check evidence; deployed readiness/smoke or pending target verification:
- E2E shared-state restoration and scoped cleanup, when applicable:
- Delivery order, recovery limitations and cleanup obligations:
- Documentation/contracts updated:
- Findings with code path, applicable requirement and concrete consequence:
- Remaining risks and owner of follow-up:

Use the parts relevant to the change. A checked box is not execution evidence.
Separate merge readiness from rollout/production acceptance.
