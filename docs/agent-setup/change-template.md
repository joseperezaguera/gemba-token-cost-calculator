# Change design — task-specific template

## Outcome and acceptance
Observable behavior; independent scenarios, including important failure cases.

## Scope and current behavior
Entrypoints, affected components/consumers, evidence paths; exclusions.

## Design and decisions
Applicable conventions/ADRs, alternatives, boundaries and invariants affected.

## Increment plan
Each step's behavior, compatibility, checks and relation to the whole.

## Verification
Scenario -> test/procedure -> expected evidence. Record unavailable checks explicitly.

## Delivery and recovery
Step -> detectable signal -> verification -> owner -> gate.
Deployment order, migration/backfill, observation criteria, recovery limits and cleanup.

## Open questions
Resolve behavior/contract ambiguity before dependent implementation.
